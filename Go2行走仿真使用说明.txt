Go2 行走仿真使用说明
阶段：Baseline 第一项——行走控制接入
新电脑请先读 新机部署说明.txt：使用 首次部署机器狗.cmd 和 运行本机部署机器狗.cmd，不要求笔记本盘符或旧私钥。以下保留笔记本原环境操作说明。

一、启动
双击桌面“Go2行走仿真（ROS2）”，再点击“启动 Go2 行走环境”。
也可以双击本目录的“运行Go2行走仿真.cmd”，打开同一个启动器。
等待 Ubuntu 自动登录，并打开 Gazebo 和“Go2 行走控制”面板。
首次窗口较小时，双击 QEMU 标题栏最大化。
看到“关节：12/12”和“控制器已激活”，待机器狗站稳后再操作。

二、操作与验收
1. 按住“前进”1～3 秒，观察四条腿交替运动、机身实际前移；松开后应停止。
2. 按住“左转”或“右转”，观察机身转向；松开停止。
3. “后退”用于低速后退。空格和面板中央“停止”均可停止移动。
4. 方向键也可控制，需要先让行走面板获得焦点。取消连续按住10秒的截断；松开、失焦或空格仍会停止。
5. 点击“居中并跟随机器狗”可调整观察视角；这只移动观察相机，不改变机器狗位置。
6. 点击“停止仿真”，等提示停止后点击“启动仿真”，应重新加载并站稳。
若机身明显侧翻，停止仿真后重新启动；本阶段没有自动翻身功能。
“速度调参”可输入任意有限数字，不设前进/后退/转向的人工上下限；零、负数与很小的小数均可保存，负值反转对应方向。保存时先停止；方向按钮与键盘立即读取同一份设置。

三、结束使用
回到 Windows 的“Go2 行走仿真启动器”，点击“安全关闭虚拟机”。
等待提示“虚拟机已安全关闭”、QEMU 窗口消失，再关闭启动器或关闭 Windows。
已知关机偶尔较慢，启动器可能先显示等待超时；遇到这种情况继续等待窗口退出，不立即强制结束进程。
“停止仿真”只结束 Gazebo，Ubuntu 仍在运行。

四、完成范围与来源
新环境独立使用 Ubuntu 24.04、ROS2 Jazzy、Gazebo Harmonic 和 CHAMP。
机器狗通过 CHAMP 步态、逆运动学、12 个关节的力矩控制和 Gazebo 物理运动。
Go2 模型和 CHAMP 移植来自上游社区工程，不是自行原创的机器人控制算法。
本项目增加了依赖修复、启动顺序协调、输入有效性检查、指令中断自动停止、图形操作入口和自测。
Windows 启动器与 Ubuntu 行走面板是本次编写的便捷界面；物理仿真来自 Gazebo。

当前验证对象是平地上的低速遥控行走，不包含自主避障、SLAM、YOLO 或导航。
关节状态与 IMU 已供本项自测使用；激光、相机和可用于定位的里程计链路尚待对应任务验收。
测试中的 /odom/ground_truth 仅测量仿真实际位移，不给控制器提供定位，不作为 SLAM 完成依据。
前进时可能有方向偏差；当前没有导航系统修正行进路线。

五、环境与入口
项目代码：E:\机器狗算法应用开发\baseline\go2_jazzy
新运行环境：E:\RobotDogRuntime\jazzy
当前使用的虚拟磁盘：E:\RobotDogRuntime\jazzy\robot-dog-clean.qcow2
资源：8 个虚拟 CPU、12GB 内存；图形后端为 SDL / VirtIO-VirGL。
已启用性能核心调度，Ubuntu 桌面为 1280×768，关闭桌面合成和观察画面抗锯齿。
鼠标或键盘被虚拟机捕获时，按 Ctrl＋Alt＋G 释放。
已在 Ubuntu 内核对渲染器为 NVIDIA GeForce RTX 4060 Laptop GPU，经 VirGL 使用。
这属于虚拟图形加速，没有进行 GPU 直通，也没有为虚拟机独占分配显存。
旧版“运行机器狗.cmd”和原 ROS Noetic 环境保留；eNSP、VirtualBox 及 Windows 虚拟化/安全设置未更改。

六、验证记录与状态
量化结果、源码版本、冷启动记录及工程限制见“行走控制验证记录.txt”。
本项只有在用户按上述步骤检查并明确认可后，才标记为“用户已验收”。
验收前不自行开展 SLAM、检测或导航等下一项功能。

七、首次黑屏或无响应的启动加固（2026-10-27）
本轮已增加分步启动检查、防止重复启动、启动超时说明和上一轮日志保留。
先关闭旧启动器窗口，再从原入口重新打开，才能加载新版代码；当前虚拟机可继续使用。
本机两次正常关闭后重开验证通过，仍不能保证 Windows 重启后的首次启动不再挂起。
若再次出现黑屏/无响应，请保留现场与 jazzy/startup-history、startup-events.jsonl，供继续定位。
详情和证据见“虚拟机启动排查记录.txt”；未在台式机现场验证。
