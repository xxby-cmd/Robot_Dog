激光、相机与里程计：原理与本项目接口
更新：2026-10-29

当前状态：台式机已完成传感器与距离自测；本轮继续优化里程计累计漂移，具体实测和限制见 context/01-CURRENT-TASK.md。
笔记本未实机复测当前版本；台式机自测不等于用户验收。
具体停点见 context/01-CURRENT-TASK.md；本轮合并保留远端头部碰撞、速度调参和共用启动器。

一、这一项解决什么
行走控制回答“怎样迈腿”；传感器和里程计回答“周围有什么、离多远、我刚才怎样移动”。
本项接通真实运行的数据流和坐标关系。地图、目标检测、导航和探索仍属于后续任务。

二、激光雷达
真实飞行时间雷达用光往返时间求距离：d = c·Δt/2。
已知光束方向与距离，就能得到三维点 p = d·方向向量；许多点组合成 PointCloud2。
Gazebo 通过渲染场景的几何深度模拟测距，不是真的在计算光传播。
本项目沿用上游 L1 外观、安装位置与倾角，默认 360×16 条规则射线，10 Hz，0.8～30 m；可提高到原上游 600×30。
它是常规三维雷达近似，不复刻真实宇树 L1 的扫描轨迹、所有噪声和材质响应。
话题：/unitree_lidar/points；坐标系：lidar_l1_link。
点的位置最初相对雷达表达，必须乘雷达到机身的变换，才能与机身或其他传感器叠加。
本项不预先选 SLAM 算法，也不把三维点云随意当成二维扫描。

三、彩色与深度相机
彩色图像提供像素颜色，供以后 YOLO 检测。深度图提供沿相机光轴的 Z 距离。
针孔模型：X=(u-cx)·Z/fx，Y=(v-cy)·Z/fy；fx/fy/cx/cy 来自 CameraInfo 内参。
所以只有图像不足以做三维定位，还要有深度、相机内参和相机外参。
本项目的 D455 是自包含的理想 RGB-D 仿真，默认 320×240，10 Hz，0.1～10 m；可提高到 640×480 / 15 Hz。
它不需要实体 RealSense 驱动，也不是厂商经过标定的硬件模拟器。
保留原上游安装位置，去掉未安装的 realsense2_description 模型依赖。
激光和相机作为机载测量挂点，不额外添加质量/碰撞体，保留已验收的机器人动力学。
这项配置不用于研究额外挂载负载；需要负载实验时再明确质量、惯量和控制调参。
不转发本项未使用的 /d455/points，以免重复 RGB-D 三维数据开销；三维激光点云仍开启。
话题：/d455/image（rgb8）、/d455/depth_image（32FC1，米）、/d455/camera_info。
图像坐标系统一为 d455_camera_optical_frame：x 向右、y 向下、z 向前。
机身使用 ROS 常规轴：x 向前、y 向左、z 向上；二者之间有固定旋转。
当前图像理想且无畸变；不要据此推断实体设备的深度误差或低光性能。

四、四足机器人的里程计
里程计是连续的局部位姿估计，不是“给了多少速度命令就认为走了多远”。
1. 用实际 /joint_states 的 12 个关节角，通过 CHAMP 正运动学求脚相对机身的位置 r。
2. 根据 Gazebo 脚部接触传感器，选取相邻两帧都落地且受力超过2N的脚。接触状态按250Hz发布，超过6ms无新接触消息则过期，不把无受力的接触记录作为支撑。
3. 近似支撑脚在世界中静止，则机身速度 v = -dr/dt - ω×r。
   ω 来自 IMU；第二项补偿转动，否则身体转弯会被误算成平移。
4. 多只支撑脚的速度逐轴取中位数，并按各脚分歧增大协方差。三脚以上时能减小单脚异常影响；只有两脚时仍是二者平均，不能据此辨认两脚共同滑动。保留切换接触、过期消息、无效关节和异常速度保护。
5. 原始观测 /odom/leg 包含身体速度和估计高度；其 x/y/yaw 不是位置估计，不参与融合。
6. robot_localization 的 EKF 融合腿部速度/高度与 IMU 的横滚、俯仰、角速度和线加速度，输出 /odom。
   用IMU姿态移除重力，当前世界实际重力大小为9.8m/s²；加速度提供接触切换时的速度预测，腿部反馈继续约束积分漂移。没有单独用IMU双积分代替腿部里程计。
   不融合仿真 IMU 的绝对 yaw，不订阅 /cmd_vel 或 Gazebo 真值。
   IMU系统由世界文件统一加载，去掉模型中的重复实例；实际200Hz独立采样，保留原角速度与加速度高斯噪声及消息协方差。

EKF 可以理解成“先预测、再按可信程度修正”：
预测：x预测=f(x上次, Δt)，P预测=F·P·F转置+Q；
修正：K=P预测·H转置·(H·P预测·H转置+R)逆，x更新=x预测+K·观测残差。
P 表示状态不确定性，Q 表示模型误差，R 表示传感器观测误差；K 决定修正幅度。
本项初始协方差是工程起点，不宣称已经做过统计标定。
IMU 的仿真姿态是较理想的传感器输出；真实硬件通常还需要姿态解算、偏置与噪声标定。
脚打滑、接触判断错误、腾空和运动学误差都会让里程计漂移。
高度估计按同一水平地面与脚球半径处理，本阶段验证地面为平地；不承诺台阶/斜坡精度。
SLAM 后续会利用环境匹配减小累计位置误差，不能靠本项消除长期漂移。

五、时间与坐标链
所有节点 use_sim_time=true，统一采用 /clock；消息频率按“仿真秒”评价。
例如实时因子 0.5 时，10 仿真 Hz 约等于每现实秒 5 帧，不要混淆性能与时间戳错误。
当前 TF：odom → base_link → trunk/imu_link/lidar_l1_link/d455_camera_link → 相机光学坐标系。
robot_state_publisher 提供机器人内部变换；只有本项 EKF 发布 odom → base_link。
此阶段不发布假的 map → odom；后续由 SLAM 接管地图坐标关系。
/odom/ground_truth 只给验证器评价误差，不给里程计、控制或滤波器作为输入。

六、安装与启动
新电脑首次安装：按 新机部署说明.txt 操作；首启配方已包含本项源码、工具和依赖。
已有部署：先在 Ubuntu 面板停止仿真并关闭面板，虚拟机保持开机。
推荐用共享启动器“应用工程更新”同步、编译并重新打开面板；备选双击“更新传感器与里程计.cmd”。
Windows 仓库内运行：python baseline/go2_jazzy/deploy_sensors.py
当前更新器统一读取本机配置，可用 --config 指定；--legacy-laptop 仅保留历史参数兼容，不再导入旧的写死盘符 SSH 常量。
更新会先备份来宾现有源码和工具，再编译；备份路径在更新输出中。
Ubuntu 重新运行 ~/bin/start-panel.sh，勾选“启用激光、深度相机与里程计”。
点击“查看实时传感器”看彩色、深度、点云俯视和里程计；方向控制方法保持原样。
取消勾选并重启仿真可回到原来的纯行走模式。
命令行入口：~/bin/start-sensors.sh；无 Gazebo 观察窗口时可加 gui:=false。
不同时启动两个仿真，不同时用自动验证器和面板发送运动命令。
台式机可在停止面板仿真后手动提高采样：
~/bin/start-sensors.sh camera_width:=640 camera_height:=480 camera_rate:=15 lidar_samples:=600 lidar_channels:=30
这是质量/开销参数调整；物理步长、碰撞和关节控制频率保持原值。

七、自测与用户验收
在来宾已启动传感器仿真的情况下，新开终端：
source /opt/ros/jazzy/setup.bash
source ~/ros2_ws/install/setup.bash
python3 ~/bin/verify_sensors.py --motion
--motion 会实际移动机器狗；不带参数只检查静态数据链。
默认报告 ~/sensor-verification/report.json、运动轨迹 trace.csv；可用 --output 指定新目录。
自测检查内容、消息频率/时间戳、TF 时间可用性、运动方向、短程误差与静止漂移。
频率下限与误差阈值公开在报告和代码中；通过短程测试不代表长期定位精度。
用户验收：看到真实更新的三类画面；移动时图像/点云变化，里程计方向符合操作；停止后位置趋稳。
要记录是否能接受开启传感器后的流畅度；仍有严重卡顿时不能只凭数据 PASS 宣告体验已通过。
本项只有自测通过并经用户确认后，才进入 SLAM 方案选择与建图任务。

八、台式机新增距离对照测试（2026-10-27）
Windows 双击“运行距离测试.cmd”。需先开启传感器模式并等待关节就绪；测试期间不要操作方向按钮，测试器保持零速度，不自行走向障碍物。
命令行等价入口：py -3 baseline/desktop_install/vm.py verify-distance。
测试在机身前方1.5米、3米各创建一堵临时静态墙，分别收集至少5帧深度和5帧激光；成功或失败均尝试移除临时墙，拒绝并发的同类验证。
每帧依据原消息时间匹配真值姿态及固定外参，仅用于独立评价；不设机器人位姿，不把真值输入里程计或控制。
相机比较光轴Z，不把斜射线距离误当Z；激光比较各射线到已知墙面的径向距离，二者预期数值不同。
报告给出实际/预期米数、样本量、中位绝对误差、95%误差和清理结果。中位误差阈值为深度3厘米、激光4厘米，95%阈值为对应数值的两倍；这是本阶段理想仿真检查，不代表实体D455或L1精度。
本机报告自动下载到运行目录 verification/ranges/时间戳/，包含 report.json、trace.csv、test-output.txt；失败报告也保留。
来宾完整验证可执行 python3 ~/bin/verify_sensors.py --ranges --motion --output ~/sensor-verification/自定义目录。
--motion 会实际低速前后移动和左右转；前后位移误差改为各自起始机身坐标下的二维端点误差，阈值 max(0.12米, 实际位移的35%)，不能把通过阈值写成精确定位。转向与直行均检查航向误差；停止还核对实际机身与估计位姿漂移。
报告另列 motion_summary，给出整组动作后的相对累计端点误差；超过12厘米时标记 cumulative_drift_warning。单段检查通过不等于累计漂移合格。旧版历史两组约14～19厘米，本轮优化结果见制作记录/里程计漂移优化_20261029/，不能据此承诺长期定位或导航精度。
新增 --max-cumulative-error 0.10：配合 --motion 使用，累计二维端点误差超过10厘米时整次验证失败；不指定时保留原诊断模式。
--motion-profile standard 为原前进/后退/左转/右转序列；reverse-first 改为后退/右转/前进/左转，速度0.10/0.12m/s、角速度0.20rad/s，运动时长4/3/5/3个仿真秒，各段后继续静止2秒。
例如：python3 ~/bin/verify_sensors.py --motion --motion-profile reverse-first --max-cumulative-error 0.10 --output ~/sensor-verification/新的唯一目录。
频率按不重复的消息时间戳计算，同时列消息总数、独立采样数和重复数；不把同一时刻的重复IMU读数当作采样率翻倍。IMU重复率超过1%验证失败。

九、实时窗口中的距离读数
“查看实时传感器”新增相机中心9×9像素区的有效深度中位数，以及激光点变换到机身坐标后、前方0.5米宽区域内相对头部碰撞包络的距离。
点云变换使用该消息时刻的TF；米数保留两位。深度处理中保留行填充和字节序，不把NaN、Inf、零值当距离。
“无有效回波”与“等待/超时”不等于零距离或道路安全；激光0.8米盲区、回波稀疏及可视范围限制仍存在。窗口只读，不自动避障。
主控制面板已压缩间距，使传感器控件、停止和状态在1280×768桌面可见，不改变速度设置与原有保护。

十、台式机本机兼容诊断边界
本轮SDL早期停顿后，GTK显示启动成功；随后出现过来宾系统进程崩溃，不能当作传感器源码编译错误。
保持相同8核/12GB、IRQ选项及构建代码，仅在这个Linux来宾本次关闭透明大页后，重新编译及完整传感器/测距/运动验证通过；底层根因仍未确认。
该台式机本机配置可显式保存 guest_thp="never"，共享入口在来宾SSH开放后应用并核对。其他电脑默认不应用；跨电脑恢复配置时移除这个硬件诊断选项，不改Windows虚拟化/安全设置，不重建磁盘。
这是一项待继续观察的本机兼容措施，不推广为所有QEMU或Intel电脑都需要，不把一次重启/测试通过说成长期稳定性根治。
2026-10-29补证：guest_thp=never下仍出现过多系统进程同地址SEGV及init内核panic，已记录并恢复，本轮最终运动及正常重启检查通过；不能将该选项视为根治。里程计短程精度改善与虚拟化长期稳定性是两项不同结论。
