新电脑从 GitHub 安装与接手
日期：2026-10-27；适用 Windows 10/11 x64。

一、这一版不需要向笔记本索取运行盘
仓库已包含控制源码、安装脚本、启动工具、项目规则、规划、交接上下文和验证证据。
新机部署入口会下载固定版本 QEMU、Ubuntu 基础镜像、便携解压工具和 ISO 生成库，并核对 SHA256。
工具只放在本项目关联运行目录，不运行 MSI 安装动作，不注册 QEMU、不安装 Windows 服务。
之后使用 Git 中的源码生成安装介质，在新电脑生成自己的 SSH 密钥，创建独立的 60GiB 动态虚拟磁盘。
Ubuntu 首次启动后自动安装 XFCE、ROS2 Jazzy、Gazebo Harmonic，编译 CHAMP 和 Go2，打开图形控制面板。
没有公开的旧运行盘下载地址，也不需要复制旧 SSH 私钥；新机可以完全重新构建。

二、新电脑 Codex 先读的三个入口
1. AGENTS.md：本阶段规则、授权边界及验收要求。
2. context\01-CURRENT-TASK.md：现在的进度、停点与下一步。
3. 本文件：部署流程和故障处理。需要决策背景时再读 context\02-CURRENT-DECISIONS.md。
项目规划.txt 和课程 docx 也已在仓库中；不需要访问原聊天记录或笔记本的私人目录。

三、准备 Git 和 Python
如已能克隆仓库，可沿用现有 Git；推荐克隆到路径较短的新目录，先保留台式机旧项目和虚拟机。
Python 需要 3.11 以上及 Tcl/Tk。推荐从 https://www.python.org/downloads/windows/ 安装 Python 3.12 或以上。
也可使用 winget install --id Python.Python.3.12 -e，安装后重新打开终端，运行 py -3 --version。
检查 Tkinter：py -3 -c "import tkinter; print(tkinter.TkVersion)"。
Git 官方下载：https://git-scm.com/download/win 。不要求 D:\Python 或 E: 盘存在。

四、克隆与检查
在新电脑执行：
  git clone https://github.com/xxby-cmd/Robot_Dog.git Robot_Dog-Desktop
  cd Robot_Dog-Desktop
  py -3 baseline/desktop_install/bootstrap.py preflight
也可获取 codex/desktop-handoff-20261027 分支；部署补齐后默认 main 与该交接分支都会更新。
preflight 只读检查。windows_x64、python_supported、tkinter、ssh_client、whpx 都应为 true。
preflight 输出 true 只说明这些前置条件可用，不代表图形性能、运动或整个 Baseline 已验收。

五、前置条件缺失时
Python/Tkinter 缺失：修改 python.org 安装，补装 Tcl/Tk，不用其他软件里的残缺 Python 代替。
OpenSSH 客户端缺失：只需要客户端，不需要安装或启用 SSH 服务器。
如需补装，可由新机 Codex 使用 Windows 可选功能，或在管理员 PowerShell 执行：
  Add-WindowsCapability -Online -Name OpenSSH.Client~~~~0.0.1.0
这是客户端依赖，部署脚本不会自动修改 Windows 功能。
WHPX 为 false：先检查硬件、Windows Hypervisor Platform 和现有 eNSP/VirtualBox 的关系。
任何需要改变 Windows 虚拟化/安全设置的方案，必须先向用户说明影响并询问；不能自动执行历史冲突修复脚本。
可先用 --prepare-only 只准备下载与安装文件，但不会启动虚拟机，不能称为安装运行完成。

六、安装
在仓库根目录执行：
  py -3 baseline/desktop_install/bootstrap.py install --start --wait
或者双击“首次部署机器狗.cmd”。首次安装需联网，系统依赖的下载和编译可能持续较长时间，以日志为准。
默认运行目录是仓库旁的 RobotDogDesktopRuntime，默认本机配置是仓库根目录 .robotdog-desktop.local.json。
CPU、内存按新机资源生成初值；SSH/QMP 端口选择空闲的一对；不覆盖任何已有的不属于本部署的运行目录。
建议目标磁盘有至少 25GiB 可用空间；60GiB 是动态虚拟容量，不会一次占满 60GiB。
如需指定目录和资源：
  py -3 baseline/desktop_install/bootstrap.py install --runtime D:\RobotDogDesktopRuntime --cpus 8 --memory 12288 --start --wait
目录须在 Git 仓库之外，路径可含中文和空格；使用空格时在命令参数外加双引号。
私钥和本机配置均不上传 Git；不要把运行目录复制到仓库内提交。

七、以后启动、关闭和验证
双击“运行本机部署机器狗.cmd”，或使用安装时创建的桌面“Go2行走仿真（本机部署）”。
这是新机入口；原“运行Go2行走仿真.cmd”保留为笔记本历史入口，不要求新机沿用其 D: / E: 路径。
安装结束不等于可以立刻移动；等待行走面板关节 12/12、控制器激活，并观察机器狗站稳。
按住方向按钮移动、松开停止；空格停止；Ctrl+Alt+G 释放 QEMU 鼠标。
检查实际渲染器：py -3 baseline/desktop_install/vm.py gpu
正常关闭：py -3 baseline/desktop_install/vm.py shutdown，或点击本机启动器“安全关闭虚拟机”。
等待进程退出、磁盘释放后再拷盘或检查磁盘；不能只按固定秒数等待。
运行完整行走自测：py -3 baseline/desktop_install/vm.py verify
测试期间不要同时操作方向按钮。结果保存到关联运行目录 verification 中，与笔记本历史证据分开。
新机测试通过后仍须用户验收；不自动进入 SLAM、检测或导航任务。

八、安装中断与诊断
查看安装日志：py -3 baseline/desktop_install/bootstrap.py logs
继续等待已运行的首次安装：py -3 baseline/desktop_install/bootstrap.py wait-install
确认首次安装 FAILED 并解决原因后重试：py -3 baseline/desktop_install/bootstrap.py retry-install
随后再次 wait-install；不要删除或重建已安装磁盘。已完成或仍在安装中的实例不能用 retry-install 重装。
重复 install 会保留已准备好的磁盘；安装准备未完成时按本机配置续传，不覆盖其他环境。
QEMU 无窗口或立即退出：看运行目录 jazzy\qemu.log；不要盲目加 -cpu host，笔记本曾因此触发 WHPX 错误。
图形卡顿：检查 gpu 的实际渲染器、Windows 负载、Gazebo 实时因子；不能把 glxgears 帧率当成 Gazebo 帧率。
本机 CPU 的性能核心会自动识别，仅影响此 QEMU 进程；同构 CPU 保留默认，不照搬笔记本 CPU 编号。
显示后端、资源等保存在本机配置中；必须正常关闭实例后再改 display / cpus / memory_mib。

九、网络、下载和软件源
全部固定 URL、版本和 SHA256 在 baseline\desktop_install\assets.json，脚本不依赖 GitHub Releases 中的私人运行包。
如下载被本机失效代理阻挡，可为本次资产下载加 --direct；不会修改系统或 Git 全局代理。
Ubuntu 与 ROS apt 默认使用清华 TUNA HTTPS 镜像，下载仍由签名和包哈希验证。
首次准备时可指定 --ubuntu-mirror https://archive.ubuntu.com/ubuntu/ --ros-mirror https://packages.ros.org/ros2/ubuntu/。
网络受限时，可按 assets.json 用浏览器下载原始文件，再传入 --local-asset 名称=文件路径，仍会校验哈希。
支持名称为 qemu、ubuntu、sevenzip、pycdlib；不能替换为未核实的随机版本或跳过校验。
校验失败的文件不会作为有效安装源；保留错误日志，检查下载和资产版本，不关闭 TLS 或软件源签名校验。

十、后续开发的文件位置
新机 Python 连接工具：baseline\desktop_install\vm.py，支持 exec / upload / download / status / gpu / verify。
来宾源码：/home/robot/ros2_ws/src/go2_champ；工作区：/home/robot/ros2_ws；工具：/home/robot/bin。
Git 中 vendor 的修改不会自动进入虚拟机。新机 Codex 需正常停仿真、上传对应源码、编译受影响包、重新启动并自测。
不要使用 retry-install 代替正常源码更新；它只处理首次安装失败。
重新制作安装介质前须关机并确认磁盘独占；已完成实例不会因为重复 install 自动重装。
源机旧 Noetic 工具已归档在 baseline\legacy_noetic，完整课程资料和已有算法源码仍在原目录。

十一、验收与事实边界
部署工具已经在笔记本的新建隔离目录测试下载/校验、便携解压、生成本机密钥、独立磁盘与 ISO、幂等保护等链路。
这不等于已经在目标台式机验证过硬件兼容、首次安装、显示性能或完整运动；这些必须在新机实测并记录。
当前 Baseline 仍是行走控制自测通过待用户验收；性能优化结果和限制见 虚拟机性能优化记录.txt。

十二、首次黑屏/无响应的后续加固（2026-10-27）
新版本启动器先检查 QEMU 监控响应，再启动 Ubuntu，并等待实际图形服务响应；不能只以进程/端口存在判断成功。
同一实例的并发启动/关机被拦截；上一次启动日志保存在运行目录 jazzy/startup-history/时间戳/。
当前步骤见 jazzy/startup-status.json，历史步骤见 jazzy/startup-events.jsonl，也可点击启动器“查看启动检查记录”。
启动或图形检查超时会保留进程和日志，不自动强杀虚拟机或重建磁盘。
笔记本两个正常关机后重开测试通过；这不是台式机实测，也没有覆盖 Windows 重启后的首次启动。
首次黑屏根因尚未完全确认，详见 虚拟机启动排查记录.txt；新电脑更新代码后仍需现场验收。
